# Rollback seguro da migration 202608050003

O rollback operacional é aditivo e não destrutivo. Não apagar `product_promotions`, snapshots, auditorias, funções ou colunas.

## Procedimento

1. Desligar preços promocionais e campanhas:

```sql
update public.marketing_settings
set pricing_enabled = false, enabled = false
where id = 1;
```

2. Confirmar que `resolve_product_price_details_v2` retorna `price_source = 'normal'` para uma amostra do catálogo.
3. Reimplantar o commit anterior da aplicação. O código anterior continua compatível porque `create_trusted_order` permanece disponível.
4. Manter a tabela e os snapshots para diagnóstico e reativação posterior.
5. Se a falha estiver apenas na migration durante a aplicação, a transação do Supabase reverte automaticamente todo o DDL.

## Verificações do rollback

- contagem de produtos e pedidos não muda;
- nenhum pedido histórico é atualizado;
- estoque não é alterado pelo desligamento;
- catálogo volta ao preço normal;
- pedidos continuam sendo criados pela RPC confiável;
- os dados de promoções individuais ficam preservados, apenas inativos pela flag.

Uma remoção física das estruturas não faz parte deste rollback porque seria destrutiva e eliminaria auditoria/dados de configuração.
